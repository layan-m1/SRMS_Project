# SRMS_Project
Student Record Management System (SRMS)
A robust, terminal-based Java application designed for universities to manage student records efficiently. The system utilizes Core Java concepts, Object-Oriented Programming (OOP) principles, Exception Handling, File I/O, and Multithreading to handle dynamic data streams, auto-save operations, and filtered academic reporting across multiple departments.

Features:
1-Dynamic Data Management: Perform complete CRUD operations (Add, View, Update, and Delete students) directly from the command line interface.
2-Dynamic Departments: Track and assign students to any university department (e.g., CS, IT, IS) seamlessly without pre-configuring separate database fields.
3-Real-Time Data Persistence (Auto-Save): Uses a background daemon thread (AutoSaveThread) that backs up all current records automatically every 60 seconds to a flat text file.
4-Startup Data Recovery (Load): Automatically searches for and reloads previously saved student records (students.txt) on application startup, ensuring historical data is never lost.
5-Multithreaded Reporting System: Utilizes a dedicated ReportThread to print standard institutional statistics or customized lists without blocking core operations.
6-High-Achiever Tracking: A built-in filtering utility that immediately targets and displays top-performing students (GPA > 4.0).
7-Custom Exception Control: Enforces strict academic validation rules using a custom InvalidGPAException to prevent incorrect or flawed institutional inputs.

System Architecture & Java Concepts Used:
1-Object-Oriented Programming (OOP):
-Inheritance & Polymorphism: Student extends a foundational Person superclass, inheriting generic structural traits while adding university-specific variables.

-Encapsulation: All critical information fields (such as studentID, studentGPA, etc.) are declared as private and accessed securely through strict controlled getters and object re-instantiation blocks.

2-Multithreading:
-Daemon Threads: The AutoSaveThread runs silently in the background as a daemon to handle file backups sequentially without blocking the primary application window.

-Thread Coordination: The ReportThread uses .join() in the main execution block to maintain a seamless, orderly terminal output sequence.

3-Robust Data Validation:
-Explicit try-catch structures isolate and manage formatting faults, missing local files, or runtime numerical errors cleanly.

Project Structure:
├── src/
│   ├── Main.java                # Application entryway and system menu control loop
│   ├── Person.java              # Foundational base class containing generic info
│   ├── Student.java             # Specialized subclass representing individual student models
│   ├── Department.java          # Model representing university academic departments
│   ├── StudentManager.java      # Core engine implementing collection logic and CRUD workflows
│   ├── AutoSaveThread.java      # Background daemon thread handling auto-saving routines
│   ├── ReportThread.java        # Independent print thread handling systemic reporting
│   └── InvalidGPAException.java # Custom business exception guarding numerical boundaries
└── students.txt                 # Local flat-file text database auto-generated by the system

How to Run the Application:
Prerequisites:
-Make sure you have the Java Development Kit (JDK 8 or higher) installed on your machine.
-An IDE or Text Editor (e.g., Visual Studio Code, IntelliJ IDEA, or Eclipse).

Execution Steps:
1-Clone the Repository or Open the project folder in VS Code:
git clone https://github.com/layan-m1/SRMS_Project.git
cd SRMS_Project

2-Compile all Java source files:
javac *.java

3-Execute the Main entry file:
java Main

Usage & Terminal Interface:
When launched, the system displays an interactive numeric menu. Enter your choice (1-6) to interact with the database:

=== Welcome to Student Record Management System ===

Select an option:
1. Add a New Student
2. Update Student GPA
3. Delete a Student
4. Generate Department Report
5. View Top Students (GPA > 4.0)
6. Exit System
Enter your choice:

Flow Walkthrough:
-Adding Students: Option 1 prompts for Name, Age, ID, GPA, and Department name dynamically.
-Automated Actions: The system automatically outputs Previous student records loaded successfully! if an existing students.txt file is recognized on launch. Every 60 seconds, you will see a background acknowledgment: AutoSave All student records saved safely to students.txt.
-Top Performers: Option 5 immediately prints accounts matching elite institutional criteria (GPA > 4.0).
